## 작업: 에이전트 엔진 2단계, 기업 하나로 처음부터 끝까지 한 번 관통하기 (walking skeleton)

### 배경
수집(1번 칸)은 `tools/collect.py`로 이미 돼 있어. 엔진은 칸이 네 개야:
수집 → 공통 표·출처 목록 → 지표 계산 → 주장·숫자 대조.
이번 작업은 나머지 세 칸을 **가장 얇게** 만들어서, 기업 하나를 넣으면 지표 표·주장 대조 표·출처 목록이 끝까지 나오게 하는 거야.
예쁘게 만드는 게 목적이 아니라, "글에 나오는 모든 숫자를 원본 줄까지 거꾸로 따라갈 수 있다"는 가정이 실제로 되는지 가장 싸게 확인하는 게 목적이야.

### 이 레포와 조별 산출물의 경계
- 이 엔진은 세 조가 모두 쓰는 공통 도구야. 특정 조의 산출물 양식(1조의 5쪽 리포트, 검증 기록지 ②~④ 등)은 여기 넣지 마.
- 조별 산출물은 엔진의 출력 세 가지(지표 표, 주장 대조 표, 출처 목록)만 읽어서 만든다. 1조 산출물 계획은 형민 개인 레포 `kfa-ai-agent`의 `docs/plans/research-center-step1.md`에 있고, 이 작업이 끝난 뒤에 시작해.

### 범위
- 넣는 것: DART 재무(2개 연도), 주가(FinanceDataReader) 두 소스. 지표 4개. 주장 3개(내가 손으로 씀).
- 안 넣는 것: Gemini 호출, 조별 산출물 양식, PER·동종사 비교, 드라이브 수동 입구, 꾸미기.
- `collect.py`의 공통 표 15칸은 **바꾸지 마.** 스터디원 노트북이 이 모양에 기대고 있어. 새로 필요한 칸은 엔진 쪽 사본에만 붙여.

### 지켜야 할 불변식 (코드보다 먼저)
1. 지표의 값은 그 지표에 적힌 입력 줄만으로 다시 계산할 수 있어야 한다.
2. 입력 줄이 없거나 `확인 필요`면 지표 값은 비워 두고 `확인 필요` + 이유를 적는다. 추정값으로 채우지 않는다.
3. 주장에 적힌 숫자는 반드시 근거 하나 이상을 가리킨다. 근거는 지표(`M#`) 또는 공통 표의 원본 줄(`rid`) 둘 중 하나. 원본 값을 그대로 인용할 때 같은 숫자를 지표로 또 만들지 않는다 (사실 하나에 정의 하나). 가리키는 게 없으면 그 주장은 `REVIEW`.
4. 출처 번호 [S#]는 같은 입력이면 매번 같은 번호가 나온다.
5. 같은 사실(종목·항목·기준·기준일·출처)이 두 줄이면 멈추고 알려준다.

### 1. 줄 번호와 출처 목록 (`tools/engine.py`)
- `with_ids(records)`: 공통 표 사본에 `rid` 칸을 붙여 돌려줌. rid = 종목코드|항목|기준|기준일|출처. 겹치면 불변식 5로 에러.
- `build_sources(records)`: 출처 하나 = 한 줄. 칸: `source_id`(S1, S2...), 출처, 출처 URL, 수집 방법, 신뢰도, 기준일 범위, 줄 수. records 사본에도 `source_id`를 붙임.

### 2. 지표 계산
- 지표 정의는 표 하나로 모아 (이름, 단위, 계산식 문자열, 입력 항목 목록, 계산 함수).
- 이번 4개: 매출 성장률(YoY), 영업이익률, 부채비율, 최근 3개월 주가 수익률.
- `compute_metrics(records, specs)` 결과 칸: `metric_id`(M1...), 지표, 값, 단위, 계산식, 입력 rid 목록, source_id 목록, 기준일, 상태, 이유.
- 매출액·영업이익은 DART 4분기 = `(연간)` 항목을 쓰고, 연결/별도는 섞지 말고 연결만.
- 비율 지표는 % 단위 숫자로 저장해 (10%면 `10.0`, `0.1` 아님). 지표 표의 단위 칸에 `%`.
- 나중에 지표를 추가할 때 정의 표에 한 줄 넣는 것만으로 끝나게 만들어. 지표마다 함수를 따로 늘리지 말 것.

### 3. 주장과 숫자 대조
- 주장은 이번엔 노트북에서 내가 손으로 씀. 문장 + 근거 목록이고, 근거 하나 = (근거 id, 문장에 적은 숫자, 그 숫자의 단위):
  ```python
  {"claim_id": "C-1", "문장": "매출이 10% 성장했다", "근거": [("M1", 10, "%")]}
  {"claim_id": "C-2", "문장": "매출은 1,100억 원이다", "근거": [("<rid 그대로 복사>", 1100, "억원")]}
  ```
  rid는 길어서 손으로 치면 틀리기 쉬우니, 노트북에서 공통 표를 rid 칸과 함께 보여주고 복사해서 쓰게 해줘.
  문장에서 숫자를 자동으로 뽑는 건 다음 단계. 지금은 대조 로직이 맞는지만 봐.
- `check_claims(claims, metrics, records)`: 근거 id가 `M`으로 시작하면 지표 표에서, 아니면 공통 표의 rid에서 찾아.
  - 문장 쪽 숫자를 원본 단위로 바꾼 뒤 비교. 이번에 지원하는 단위: `원`, `억원`, `조원`, `%`. 단위가 안 맞거나 모르는 단위면 REVIEW.
  - PASS: 반올림 차이 이내 일치. 허용 범위는 문장에 적은 숫자의 마지막 자릿수의 절반 (10이면 ±0.5, 1100억원이면 ±0.5억원)
  - REVIEW: 근거 없음, 근거 id를 못 찾음, 근거가 `확인 필요`, 단위 문제
  - FIX: 불일치. 실제 값을 같은 단위로 옆에 표시
- 주장 끝의 [S#]는 근거가 가리키는 줄(지표면 그 지표의 입력 줄)의 출처 번호에서 자동으로 붙여.

### 4. 결과 출력
- `render_check(...)`가 마크다운 파일 하나를 만듦:
  - 주장 목록: 문장 끝에 [S#]
  - 지표 표: 값, 계산식, 출처 번호
  - 숫자 대조 표: 주장, 적은 숫자, 실제 값, 판정
  - 출처 목록 [S1]~[S#]: 이름, 원본 URL, 신뢰도
- 저장 위치는 `data/` (gitignore 돼 있음).

### 5. 실행 노트북 (`notebooks/03_engine_skeleton.ipynb`)
- 맨 위에 `STOCK_CODE = "<종목코드>"`, `YEAR = 2025` 두 줄만 바꾸면 돌아가게.
- 셀 순서: 수집 → 출처 목록 → 지표 → 주장 → 대조 → 결과 미리보기.
- 주장 셀 예시는 세 개: 지표 인용 하나, 원본 줄 인용 하나, **일부러 틀린 숫자 하나**(FIX가 나오는 걸 보여주기).
- 각 셀 위 마크다운은 문과생 기준 한두 줄.
- 노트북은 2회차처럼 `build_notebook.py` 방식으로 `collect.py`와 `engine.py`를 품게 할지, 따로 만들지 계획 단계에서 같이 정하자.

### 6. 테스트 (`tools/test_engine.py`)
- 네트워크 없이, 손으로 만든 작은 공통 표로:
  - 맞는 숫자 → PASS, 틀린 숫자 → FIX, 입력 없는 지표를 가리키는 주장 → REVIEW
  - 원본 줄(rid)을 억원 단위로 인용한 주장 → 원 단위로 바꿔 PASS, 없는 rid → REVIEW
  - 같은 입력 두 번 → 같은 S# 번호
  - 겹치는 줄 → 에러

### 함정 기록
- 실제 데이터에서 발견한 함정은 `docs/traps.md`에 모아. 지표나 검사를 만들 때 해당 항목을 먼저 읽고, 새 함정을 찾으면 같은 형식으로 추가해.

### 진행 방식
1. 코드 쓰기 전에 함수 목록과 각 함수의 입력·출력 모양을 계획으로 보여주고 내 확인 받기. 위 설계에 우려나 더 단순한 대안이 있으면 그때 말해줘.
2. 확인 후 작성, 로컬에서 노트북 실행해서 결과 마크다운을 그대로 보여주기.
3. 커밋 전에 `git status` 보여주고 `.env`, `data/`가 없는 것 확인. 내 확인 받고 커밋.
