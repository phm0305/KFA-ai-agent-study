## T1. 적자인 해를 기준으로 한 성장률

- **무엇:** 성장률 = (올해 − 작년) ÷ 작년인데, 작년 값이 0 이하면 분모가 음수가 돼서 부호가 뒤집히거나 의미 없는 숫자가 나와요.
- **관찰:** SK하이닉스 2023년 연결 영업이익 (7,730,313)백만원, 당기순이익 (9,137,547)백만원. 2024년엔 흑자(영업이익 23,467,319). 2023→2024 영업이익 성장률을 그대로 계산하면 음수가 나와 "감소"처럼 읽혀요.
- **처리 방향:** 분모가 0 이하면 값을 비우고 `확인 필요`, 비고에 "기준값 적자: 흑자전환 / 적자지속 / 적자확대로 표기". 리포트 관행처럼 퍼센트 대신 상태 이름으로 내보내요.
- **해당 지표:** 영업이익·순이익 성장률, EPS 성장률. 이번 4개 지표 중엔 없음(매출 성장률의 분모인 2024 매출은 양수).

## T2. 하루 급변(상한가)이 기간 수익률을 좌우

- **무엇:** 기간 수익률은 시작일 하루 차이에 크게 흔들려요.
- **관찰:** SK하이닉스 종가 2026-07-30 1,322,000원 → 07-31 1,718,000원(+29.95%, 사상 첫 상한가). 뉴스로 실제 사건 확인. "최근 3개월" 시작일이 7/30이냐 7/31이냐에 따라 시작 가격이 1,322,000원과 1,718,000원으로 갈려요.
- **처리 방향:** 지표 계산식에 기간 규칙을 글자로 적어요(예: "끝 = 마지막 확정 종가, 시작 = 63거래일 전 종가"). 기간 안에 하루 변동이 큰 날이 있으면 비고에 그 날짜와 등락률을 남겨요. "큰 변동"의 기준값은 미정.

## T3. 같은 원천을 두 번 보는 가짜 검증

- **무엇:** 수집 소스와 검증 소스가 같은 원천에서 왔으면 둘 다 틀려도 일치로 보여요.
- **관찰:** FinanceDataReader 주가는 네이버 금융을 거쳐 와요. 그래서 네이버 화면으로 대조하면 같은 데이터를 두 번 보는 셈이에요. 7/31 상한가는 뉴스로 따로 확인했어요.
- **처리 방향:** 출처 목록에 "원천" 칸을 두고(지금은 출처 이름에 글자로 들어 있음), 검증할 땐 원천이 다른 곳(한국거래소, 공시, 뉴스)을 쓰게 안내해요.

## T4. 장중에 수집한 당일 종가

- **무엇:** 장 마감(15:30) 전에 받으면 당일 줄은 확정 종가가 아니에요.
- **관찰:** 2026-10-30 수집분에 당일 줄이 들어 있었어요. 수집 시각은 장 마감 이후로 보이지만, 규칙으로 정해둔 게 아니라 운이었어요.
- **처리 방향:** 15:30 전에 수집했으면 당일 줄을 빼고 "마지막 확정 종가"를 써요. 2번(지표 계산) 때 정하기로 함.

## T5. 과거 숫자 재작성

- **무엇:** 회계기준 변경, 사업 매각에 따른 중단영업 재분류, 오류 정정 때문에 회사가 과거 연도 숫자를 다시 내요. 그러면 같은 "2024년 매출"에 값이 두 개 생겨요.
- **관찰:** SK하이닉스는 재작성 없음. 2025 사업보고서의 전기(2024) 칸과 2024 사업보고서의 당기 칸이 매출·영업이익·당기순이익·부채·자본 모두 같았고, 2023년 값도 두 보고서에서 같았어요(형민이 DART 원문에서 직접 확인).
- **왜 아직 안 부딪히나:** `collect_dart`는 보고서마다 당기 칸만 받아서 연도마다 보고서가 하나뿐이에요. 전기 칸까지 받거나 여러 해를 겹쳐 받으면 불변식 5번(같은 사실 두 줄이면 멈춤)이 먼저 걸려요.
- **처리 방향:**
  1. 두 버전을 공시일(접수번호)로 구분해 둘 다 보관
  2. 고르는 규칙은 하나: "분석 기준일 이전에 공시된 것 중 가장 최신". 리포트는 기준일 = 오늘, 백테스트는 기준일 = 과거 날짜
  3. 값이 다르면 `확인 필요` + 비고 "재작성: 이전 X → 이후 Y (공시일)". 이유는 사업보고서 주석에서 확인
  4. 탐지는 DART 응답의 전기 금액과 작년 보고서의 당기 금액을 비교(필드 이름은 실제 응답에서 확인)

## T6. 당기순이익에 비지배지분 포함

- **무엇:** `collect.py`의 당기순이익(`ifrs-full_ProfitLoss`)은 비지배지분 몫까지 합친 전체예요. ROE·EPS·PER에는 지배기업 소유주 귀속분을 써야 해요.
- **관찰:** SK하이닉스 2025 연결 자본총계 120,666,751 중 지배기업 소유지분 120,516,178, 비지배지분 150,573(백만원). 이 회사는 차이가 작지만 지주사·자회사가 많은 회사는 커요.
- **처리 방향:** `DART_ITEMS`에 지배기업 귀속 순이익·자본 계정을 추가하고, 지표 정의에서 어느 쪽을 쓰는지 이름으로 구분(예: "당기순이익(전체)" / "당기순이익(지배)"). 계정 ID는 실제 응답에서 확인.

## T7. 원 단위(API)와 백만원 단위(원문)

- **무엇:** DART API는 원 단위, 사업보고서 화면은 보통 백만원 단위예요. 리포트 문장은 억원·조원을 써요.
- **관찰:** SK하이닉스 2025 매출 API 값 97146675000000원 = 원문 97,146,675백만원.
- **처리:** `engine-step2.md` 3번에 반영. 주장 근거에 단위를 적고 원본 단위로 바꿔 비교, 모르는 단위는 REVIEW.

## T8. 출처를 이름만으로 묶으면 보고서가 섞임

- **무엇:** DART 줄은 연도와 상관없이 출처 이름이 같아서, 이름으로만 묶으면 2024·2025 사업보고서가 S1 하나로 합쳐지고 원문을 하나로만 따라갈 수 있어요.
- **처리:** (출처, 출처 URL) 쌍을 출처 하나로 셈. S#는 정렬 순서로 매겨 셀 순서가 바뀌어도 같은 번호. 1번(`build_sources`)에 반영.
- **남은 것:** 새 출처가 추가되면 기존 번호가 밀릴 수 있음. 이미 쓴 문장의 [S#]가 바뀌는 문제는 미해결.

## T9. 계정을 못 찾은 DART 줄의 기본 주소

- **무엇:** DART 응답에서 표준 계정을 못 찾은 줄은 공시 링크 대신 기본 주소(`opendart.fss.or.kr`)를 달고 별도 S#로 잡혀요. 원문까지 따라갈 수 없는 출처예요.
- **관찰:** SK하이닉스 2024·2025는 6개 계정을 다 찾아서 발생 안 함.
- **처리 방향:** 숨기지 않고 두되, 출처 목록에서 "원문 링크 없음"으로 표시.

## T10. 12월 결산 가정

- **무엇:** `collect.py`는 기준일을 12월 결산으로 가정해요(비고 "기준일은 12월 결산 가정"). 3월·6월 결산 회사면 기준일이 틀려요.
- **관찰:** SK하이닉스는 12월 결산이라 해당 없음.
- **처리 방향:** DART 기업개황 API의 결산월(`acc_mt`)로 기준일을 계산. 2026-10-08에 삼성전자 결산월 12를 이 API로 받은 적 있음.
