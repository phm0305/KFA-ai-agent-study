# 2회차 템플릿 설계 명세

`tools/collect.py`, `notebooks/02_template_collect.ipynb`, `tools/test_collect.py`, `tools/build_notebook.py`를 왜 이렇게 만들었는지 적은 문서예요.
스터디장(형민)과 Claude Code가 고칠 때 기준으로 삼아요. 조원이 읽어도 되도록 쉬운 말로 썼어요.

## 1. 이번 주 목표와 템플릿의 역할

2회차에 조원이 해야 하는 일은 노션 2회차 페이지 기준으로 세 가지예요.

| 이번 주 할 일 | 템플릿이 받쳐 주는 방법 |
|---|---|
| 담당 소스 1개를 AI로 함수로 만들어 Colab에서 돌리기. 결과는 템플릿과 같은 모양, 못 채운 칸은 비우고 이유 한 줄 | `collect_table()` 하나로 끝나면 모양이 자동으로 맞아요. 못 채운 칸은 자동으로 **확인 필요**가 되고 이유가 비고에 붙어요 |
| 소스 지도에 수집 방법 1~5단계 적기 | 1~5단계 예시를 하나씩 직접 돌려 봐요. 단계마다 무엇이 자동이고 무엇이 사람 몫인지 결과로 보여요 |
| `KFA_자료` 폴더 + 출처카드에 자동 수집 안 되는 자료 1개 넣기 | `collect_from_cards()`가 출처카드에 적힌 파일만 읽어요. 엔진 설명서의 수동 입구 규칙을 코드로 옮겼어요 |

이번 주에 정하는 **소스 지도 · 산출물 카드 · 담당 소스**가 3회차 엔진의 입력이 돼요. 그래서 이번 템플릿은 "수집 함수 예시"를 넘어서, **어떤 소스든 엔진에 꽂히는 콘센트 모양**을 미리 고정하는 데 목적이 있어요.

## 2. 설계 원칙

### 2-1. 입구는 다섯 개, 출구는 하나

```
1 공식 API      read_json_table() · collect_dart() · collect_ecos()  ─┐
2 라이브러리     라이브러리가 준 DataFrame 그대로                     ─┤
3 파일          read_table()  (URL·경로, cp949, 가짜 .xls 처리)      ─┼─▶ collect_table() ─▶ finalize() ─▶ 공통 표 15칸
4 크롤링        read_html_table()  (robots.txt 먼저 확인)            ─┤
5 수동 입력      pd.DataFrame([...]) · collect_from_cards()           ─┘
```

- 단계마다 다른 건 **표를 받아오는 부분뿐**이에요. 꼬리표 붙이기, 숫자·날짜 정리, 상태 판정은 전부 `finalize()` 한 곳에서 해요.
- 그래서 사용자 요청("1~5단계 모두에 적용 가능한 코드")을 함수 다섯 벌로 풀지 않고, **읽기 함수 몇 개 + 공통 출구 하나**로 풀었어요. 새 소스가 생겨도 읽는 부분만 AI에게 맡기면 돼요.
- 조원이 AI로 만든 코드가 이 출구를 안 거치면 `run_step()`이 ❌로 막아요. 콘센트 모양이 틀린 플러그는 엔진에 안 꽂히는 셈이에요.

### 2-2. 코드가 할 수 있는 것과 사람이 할 것을 나누는 선: 형식 통과 / 확인 필요

`상태` 칸은 두 값만 가져요.

| 상태 | 뜻 | 정하는 규칙 |
|---|---|---|
| 형식 통과 | 모양이 맞다. 숫자가 **맞다**는 뜻은 아님 | 아래 확인 필요 조건에 하나도 안 걸림 |
| 확인 필요 | 코드가 혼자 판단할 수 없어 사람에게 넘김 | 아래 중 하나라도 해당 |

확인 필요 조건 (전부 `비고`에 `⚠ 이유`로 남아요):

1. 필수 칸(항목·값·단위·기준·기준일·공시일·출처·출처 URL·신뢰도)이 비어 있음
2. 값이 숫자로 안 바뀜 (`약 3조`, `12억`). 원래 글자는 값 칸에 그대로 남겨서 사람이 볼 수 있게 함
3. 기준일·공시일 모양을 모름, 또는 없는 날짜 (`2026-02-30`)
4. 공시일이 기준일보다 빠름 (거의 항상 입력 실수)
5. 신뢰도가 상/중/하가 아님
6. `해당 없음`을 쓰면 안 되는 칸에 씀
7. **4단계(크롤링)와 5단계(수동)는 기본으로 전부.** `확인` 칸에 O를 적으면 풀려요

7번이 사용자 요청의 "하위 단계로 갈수록 코드로 할 수 있는 영역이 줄어드니 확인 필요로 사용자 판단에 넘긴다"를 그대로 옮긴 규칙이에요. 크롤링은 페이지가 바뀌면 조용히 틀린 칸을 읽고, 손으로 옮긴 숫자는 오타를 코드가 알 수 없어서예요.

**왜 "통과/실패"가 아니라 "형식 통과/확인 필요"인가:** 4회차 검증기가 원본과 대조해서 "통과 / 걸림 / 확인 필요"를 매겨요(엔진 설명서). 2회차 단계에서 "통과"라고 부르면 그 검증을 이미 한 것처럼 보여서 이름을 구분했어요.

### 2-3. 빈칸과 "해당 없음"은 다르다

- 빈칸 = **모른다** → 확인 필요
- `해당 없음` = **이 숫자엔 그 개념이 없다** (주가의 연결/별도, 거시 지표의 종목코드) → 통과

이걸 구분 안 하면 거시 지표는 전부 확인 필요가 되고, 반대로 "해당 없음"을 아무 데나 쓰면 진짜 빠진 꼬리표가 숨어요. 그래서 `해당 없음`은 종목코드·종목명·기준·공시일 네 칸에만 허용했어요.

### 2-4. 칸 15개: 무엇이 읽는가

엔진 설명서의 필수 꼬리표 7개 + 기본 정보 3개(종목·항목·수집 시각)에 다섯 칸을 더했어요. 더한 칸마다 그 칸을 읽는 곳이 있어요.

| 더한 칸 | 읽는 곳 | 없으면 깨지는 것 |
|---|---|---|
| 종목명 | 사람, 산출물 모듈 | 종목코드만 보고 회사를 알아봐야 함 |
| 출처 URL | 4회차 검증기, 사람 | 원문 대조 불가. 사전과제에서 링크 칸에 리포트 주소나 사이트 첫 화면을 넣은 경우가 많았던 문제 |
| 수집 방법 | 상태 규칙 7번, 5회차 신뢰도 논의, 소스 지도 | 크롤링·수동 값을 골라낼 수 없음 |
| 상태 | 엔진 약속 2번 "통과한 기록 + 확인 필요 목록만 넘기기" | 모듈에 넘길 줄을 고를 수 없음 |
| 비고 | 사람, 과제 요건("왜 못 채웠나 한 줄") | 확인 필요 이유를 다시 추적해야 함 |

### 2-5. 꼬리표 정책

| 꼬리표 | 정책 | 이유 |
|---|---|---|
| 공시일 | 소스가 주면 그 값. 주가·금리처럼 그날 공개되는 건 `SAME_AS_DATE`(기준일 복사, 비고에 표시). 모르면 비워서 확인 필요 | 미래 정보 참조 방지가 이 칸의 존재 이유라, 모를 때 추측으로 채우지 않음 |
| 공시일 (DART) | 접수번호 앞 8자리 | DART 응답에 날짜 칸이 따로 없고, 접수번호가 접수일로 시작함 |
| 기준일 (DART) | 연도 + 분기말, 12월 결산 가정을 비고에 적음 | 재무제표 API 응답에 기준일 칸이 없음. 결산월이 다른 회사는 비고를 보고 고쳐야 함 |
| 손익 (DART) | 1~3분기는 3개월·누적 두 줄, 1분기는 한 줄, 사업보고서는 연간 한 줄 + "4분기 = 연간 - 3분기 누적" 메모 | 3개월치와 누적을 섞는 게 대표 함정 |
| 신뢰도 | 상(공시·공식 통계) / 중(증권사 리포트·중간 사이트) / 하(기사·블로그) | 엔진 설명서 출처카드 기준과 같게. 5회차에 조별로 다듬음 |
| 신뢰도 (FinanceDataReader) | 중 | 확인해 보니 한국 주식은 기본으로 네이버 금융 차트에서 받아옴(라이브러리 코드 `data.py`). 원천(한국거래소)이 아니라 중간 사이트라 2회차 판단 질문 "원천인가, 옮겨 적은 곳인가"의 예시로 남김. 조별로 상으로 올려도 됨 |
| 단위 (DART) | 원 | API는 원 단위, 공시 원문 표는 백만 원. 엔진 설명서 예시와 같음 |

### 2-6. "모두 실행"이 절대 멈추지 않게

- 모든 예시는 `run_step(이름, 단계, 함수)`로 감싸요. 성공하면 ✅, 준비 부족(`SkipStep`)이면 ⏭, 실패면 ❌로 요약표에 한 줄 남기고 다음 셀로 넘어가요.
- 이유: 조원 20명이 각자 다른 환경에서 돌려요. 한 사이트가 막혀서 노트북 전체가 멈추면 "내 소스" 셀까지 못 가요. 환경점검 노트북과 같은 ✅/⏭/❌ 요약표 형식이라 조원들에게 익숙해요.
- 같은 이름으로 다시 실행하면 요약표의 이전 줄을 바꿔 써요(줄이 쌓이지 않음).

### 2-7. 키 보안

- 키는 `get_key()`로만 읽어요(Colab Secrets, 내 컴퓨터는 `.env`).
- 에러 메시지에는 **주소 전체 대신 사이트 이름(호스트)만** 넣어요. DART 키는 주소 뒤쪽 `?crtfc_key=`에, ECOS 키는 주소 경로 안에 들어가서, 원래 에러 메시지를 그대로 보여주면 키가 화면에 찍혀요.
- `raise ... from None`으로 원래 에러를 숨겨서, 조원이 `run_step` 없이 함수를 직접 불러도 Traceback에 키가 안 나와요.
- 테스트(`test_http_errors_hide_key`, `test_dart_errors_are_friendly_and_hide_key`)와 노트북 전체 실행 검사로 확인했어요.

### 2-8. 코드는 한 곳에만: collect.py → 노트북

- 공통 코드의 원본은 `tools/collect.py` 하나예요. 노트북은 `tools/build_notebook.py`가 그 파일을 **접힌 셀 하나**(`#@title`, 코드 숨김)에 그대로 넣어 만들어요.
- 노트북이 `import`로 불러오지 않고 코드를 품는 이유: (1) 조원 노트북이 레포에 저장될 때 **그때 돌린 코드가 같이 남아** 결과를 다시 만들 수 있고, (2) 스터디장이 레포를 고쳐도 이미 제출된 노트북이 갑자기 바뀌지 않아요.
- 3회차 엔진 뼈대는 `collect.py`를 그대로 가져다 써요. 출처카드 읽기 함수가 이미 들어 있어서 11/2 준비물이 줄어요.
- **collect.py를 고치면 반드시 `python tools/build_notebook.py`를 다시 돌려요.** 안 돌리면 노트북이 옛 코드를 품고 있어요.

## 3. 함수 명세

### 공통 출구

| 함수 | 입력 | 출력 | 실패 |
|---|---|---|---|
| `collect_table(table, items=None, date_col=None, keep=None, **meta)` | 원본 표. `items={원래 칸: (항목, 단위)}`. items가 없으면 표에 `항목`·`값` 칸이 있어야 함 | 공통 표 | `CollectError` (표에 없는 칸이면 지금 칸 목록을 같이 보여줌) |
| `finalize(table, *, level, source, source_url, reliability, basis, disclosed, base_date, stock_code, stock_name, unit, note)` | 항목·값이 있는 표 + 기본 꼬리표. **표 안에 이미 있는 값이 기본값보다 우선** | 공통 표 (15칸, 순서 고정) | level이 1~5가 아니면 `ValueError` (코드 실수라 바로 알려야 함) |
| `long_from_table(table, items, date_col=None, keep=None)` | 칸마다 항목이 하나씩인 넓은 표 | 숫자 하나 = 한 줄인 긴 표 | `date_col`이 없고 인덱스가 날짜가 아니면 `CollectError` |
| `check_records(records, show=True)` | 공통 표 | True/False + 요약 출력 (확인 필요 이유 상위 5개) | 칸 이름·순서, 상태 값, "필수 칸이 비었는데 형식 통과" 위조를 잡음 |
| `save_records(records, stem)` | 공통 표 | `stem.csv`, `stem_확인필요.csv` (엑셀에서 안 깨지게 utf-8-sig) | |
| `run_step(label, level, func)` / `step_summary()` | 예시 이름, 단계, 공통 표를 돌려주는 함수 | 공통 표 또는 None / 요약 표 | 절대 예외를 밖으로 던지지 않음 |

### 입구

| 함수 | 단계 | 하는 일 |
|---|---|---|
| `read_json_table(url, rows_path, params)` | 1 | JSON을 받아 `"a.b.c"` 위치의 목록을 표로. 위치가 틀리면 그 자리에 있는 키와 응답 앞부분 200자를 보여줌 |
| `collect_dart(stock_code, year, quarter, fs_div, api_key)` | 1 | 회사 번호표(한 번만 받아 기억) → 재무제표 → 6개 계정을 표준 코드(account_id)로 골라 공통 표 |
| `collect_ecos(api_key, stat_code, cycle, start, end, item_code, label, unit)` | 1 | ECOS 통계 1개. 키가 없으면 ⏭ |
| `read_table(source, sheet_name, skiprows)` | 3, 5 | URL 또는 경로의 CSV·엑셀. utf-8 → cp949 순서로 시도, 내용이 `<`로 시작하면 웹페이지 표로 읽음(한국 사이트의 가짜 .xls) |
| `read_html_table(url, match, index)` | 4 | robots.txt 확인(막히면 ⏭, 확인 불가면 경고만) → 표 찾기 → 2줄짜리 머리글 펼치기 |
| `find_col(table, keyword)` | 4 등 | 이름에 글자가 들어간 첫 칸. 크롤링한 표는 칸 이름이 조금씩 바뀌어서 정확한 이름 대신 씀 |
| `read_source_cards(source)` | 5 | CSV 경로 또는 Colab에서 구글 시트 제목 |
| `collect_from_cards(cards, files_dir)` | 3, 5 | 출처카드에 적힌 파일만, 항목·값 모양인 CSV·엑셀만 읽고 나머지는 이유와 함께 건너뜀. 카드의 출처·URL·기준일·신뢰도를 꼬리표로 씀 |

### 정리 도구

| 함수 | 받아들이는 것 |
|---|---|
| `to_number` | `1,234` · `(1,234)` · `△1,234`(음수) · `12.5%` · `-` `.` 빈칸(값 없음). 정수 문자열은 float를 거치지 않아 큰 금액도 정확 |
| `to_date` | `2026-06-30` · `2026.6.30.` · `20260630` · `2026년 5월 29일` · `2026-08` · `202608` · `2026Q2` · `2026` · 시각이 붙은 날짜. 결과는 `YYYY-MM-DD` / `YYYY-MM` / `YYYYQn` / `YYYY` |
