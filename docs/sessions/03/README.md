# 3회차 가이드: DART 한 종목을 출처 번호까지

2회차에는 여러 소스를 공통 표(15칸)로 받아왔어요. 이번 주에는 그 표의 줄마다 **이름표(rid)** 를, 출처마다 **번호([S#])** 를 붙여요. 나중에 글에 나온 숫자 하나를 공통 표의 줄과 원문 공시까지 거꾸로 따라가려면 이 둘이 있어야 해요.

이번 주에 할 일은 다섯 가지예요.

1. 노트북으로 DART 한 종목을 공통 표 → 꼬리표 점검 → 출처 번호 → 저장까지 돌리기
2. 내 소스를 종목 3개 이상에 붙이고, 실패한 요청을 실패 기록으로 남기기
3. 2회차에 만든 출처카드(수동 입구)가 엔진으로 들어오는지 확인하기
4. 함정 사례 1개를 내 데이터로 재현해서 적기
5. 내 레포에 `w03_엔진.ipynb`로 제출하고 판단 질문에 답 적기

전체 데이터 소스 지도는 모임 전까지 따로 공유할게요.

> ⏰ **마감**: **각 조 다음 모임 전까지** 내 레포에 제출

> 준비물: GitHub 내 레포 `kfa-ai-agent`, Colab Secrets에 `DART_API_KEY` (아직이면 [SETUP.md](../../SETUP.md) 8·9번), 2회차에 만든 구글 드라이브 `KFA_자료` 폴더와 출처카드

## 2. DART 한 종목 끝까지

노트북 **1. DART에서 두 해 받기** 셀은 사업보고서의 연결 재무제표에서 6개 계정(자산총계, 자본총계, 부채총계, 영업이익, 당기순이익, 매출액)을 두 해치 받아요. 해마다 따로 받아서, 한 해만 실패해도 어느 해인지 보여요.

아래는 기본 설정(`STOCK_CODE = "000660"`, `YEAR = 2025`, SK하이닉스)으로 돌린 결과예요. 스터디장 컴퓨터와 Colab에서 똑같이 나왔어요.

```
✅ DART 2024 사업보고서: 6줄 (확인 필요 0줄)
✅ DART 2025 사업보고서: 6줄 (확인 필요 0줄)
```

| 종목명 | 항목 | 값 | 단위 | 기준 | 기준일 | 공시일 | 상태 |
|---|---|---|---|---|---|---|---|
| SK하이닉스 | 자산총계 | 119855209000000 | 원 | 연결 | 2024-12-31 | 2025-03-19 | 형식 통과 |
| SK하이닉스 | 매출액(연간) | 66192960000000 | 원 | 연결 | 2024-12-31 | 2025-03-19 | 형식 통과 |
| SK하이닉스 | 자산총계 | 176107659000000 | 원 | 연결 | 2025-12-31 | 2026-03-17 | 형식 통과 |
| SK하이닉스 | 매출액(연간) | 97146675000000 | 원 | 연결 | 2025-12-31 | 2026-03-17 | 형식 통과 |
| … | (12줄 중 4줄만) | | | | | | |

읽을 때 볼 곳은 세 군데예요.

- **값은 원 단위**예요. 사업보고서 화면은 보통 백만원 단위라서, 2025 매출 97146675000000원은 원문에서 97,146,675(백만원)으로 보여요.
- **기준일**은 숫자가 가리키는 날(결산일), **공시일**은 그 숫자가 세상에 알려진 날이에요. 2025년 숫자를 2026-03-17 전에 알 수는 없었다는 뜻이에요.
- **기준 = 연결**은 자회사까지 합친 재무제표라는 뜻이에요. 같은 회사라도 별도(본사만)면 숫자가 달라요.

## 3. 꼬리표 점검 결과 읽는 법

노트북 **2. 꼬리표 점검** 셀은 15칸의 이름·순서와 상태 칸을 검사하고 한 줄로 요약해요. 위 DART 결과는 이렇게 나와요.

```
✅ 칸 모양 OK: 12줄 (형식 통과 12 · 확인 필요 0)
```

- `칸 모양 OK`: 15칸이 이름·순서 그대로 있어요. ❌가 나오면 공통 표 모양이 깨진 거예요(아래 "막혔을 때").
- `형식 통과`: 꼬리표가 다 채워져 있고 모양이 맞아요. **숫자가 맞다는 뜻은 아니에요.** 진짜 맞는지는 4회차 검증기가 봐요.
- `확인 필요`: 코드가 혼자 판단 못 해서 사람에게 넘긴 줄이에요. 그 아래에 ⚠ 이유가 줄 수와 함께 나와요.

확인 필요가 있으면 이런 모양이에요(6번 수동 입구에서 실제로 나온 결과).

```
✅ 칸 모양 OK: 14줄 (형식 통과 12 · 확인 필요 2)
   ⚠ 공시일 비어 있음: 2줄
   ⚠ 기준 비어 있음: 1줄
   ⚠ 손으로 옮긴 값: 원문과 대조: 1줄
```

⚠ 이유는 줄마다 하나가 아니라 여러 개일 수 있어요. 그래서 이유별 줄 수를 더하면(4) 확인 필요 줄 수(2)보다 클 수 있어요.

| 기호 | 뜻 | 할 일 |
|---|---|---|
| ✅ | 공통 표로 받아옴 | 없음 |
| ⏭ | 준비가 안 돼서 건너뜀 (키 없음, 설정 꺼짐, 아직 안 채움) | 메모 읽기. 고칠 필요 없는 경우가 대부분 |
| ❌ | 실패 | 메모 읽고 아래 "막혔을 때" 표 보기 |

## 4. 출처 목록 [S#] 읽는 법

노트북 **3. 줄 이름표(rid)와 출처 번호([S#])** 셀은 두 표를 보여줘요.

첫 번째는 **출처 목록**이에요. 출처 하나가 한 줄이에요.

| source_id | 출처 | 출처 URL | 수집 방법 | 신뢰도 | 기준일 범위 | 줄 수 |
|---|---|---|---|---|---|---|
| S1 | DART 단일회사 전체 재무제표 API | https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20250319000665 | 1 공식 API | 상 | 2024-12-31 | 6 |
| S2 | DART 단일회사 전체 재무제표 API | https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260317000635 | 1 공식 API | 상 | 2025-12-31 | 6 |

- **출처 이름이 같은데 번호가 둘인 이유**: 출처 하나 = (출처 이름, 출처 URL) 한 쌍이라서요. 2024 사업보고서와 2025 사업보고서는 주소가 달라서 S1·S2로 나뉘어요. 이름만으로 묶으면 두 보고서가 섞여서 원문을 하나로만 따라갈 수 있어요.
- **출처 URL**을 누르면 그 숫자가 실린 공시 원문이 열려요. 나중에 글에 `[S2]`라고 적으면 읽는 사람이 이 주소로 확인할 수 있어요.
- **기준일 범위**는 그 출처에서 온 줄들의 기준일 중 가장 이른 날 ~ 가장 늦은 날이에요. 하루뿐이면 날짜 하나만 나와요.
- **줄 수**는 공통 표에서 그 출처를 쓰는 줄 수예요. 다 더하면 공통 표 줄 수(12)와 같아야 해요.
- 번호는 출처 이름·주소를 정렬한 순서로 매겨서, 다시 돌려도 같은 번호가 나와요. 다만 출처가 새로 늘면 기존 번호가 밀릴 수 있어요.

두 번째 표는 줄마다 **rid**와 **source_id**를 보여줘요. rid는 `종목코드|항목|기준|기준일|출처`를 이어 붙인 이름이에요.

```
S2   000660|매출액(연간)|연결|2025-12-31|DART 단일회사 전체 재무제표 API   97146675000000
```

같은 rid가 두 줄이면 같은 사실을 두 번 넣은 거라서 엔진이 멈춰요. 같은 셀을 두 번 붙였거나 같은 파일을 출처카드에 두 번 적었을 때 생겨요.

노트북 **4. 저장** 셀은 왼쪽 📁 파일 탭에 `w03_dart.csv`(전부), `w03_dart_확인필요.csv`(확인 필요만), `w03_dart_sources.csv`(출처 목록)를 만들어요.

## 5. 내 소스를 3종목에 붙이고 실패 기록 남기기

### 5-1. 내 소스 붙이기

노트북 **✍️ 과제: 내 소스를 종목 3개 이상에 붙이기** 셀을 채워요. 2회차에 성공한 `my_records()`를 종목코드를 받는 모양 `my_records(code)`로 바꾸는 거예요.

1. `MY_LEVEL`에 내 소스의 수집 방법 단계(1~5), `MY_TARGETS`에 종목코드 3개 이상을 적어요
2. `raise SkipStep(...)` 줄을 지우고, 그 아래를 2회차에 성공한 코드로 바꿔요
3. 주소나 요청 값에 종목코드가 들어가는 자리에 `code`를 넣고, `collect_table(...)` 끝에 `stock_code=code`를 남겨요
4. 금리처럼 종목과 상관없는 소스면 `MY_TARGETS`에 통계 번호 3개를 넣고 `stock_code=code` 줄을 지워요

종목마다 ✅ ⏭ ❌가 한 줄씩 나와요. **실패한 종목은 지우지 말고 그대로 두세요.** 실패도 기록이에요.

되는 것이 확인된 내 소스 함수는 조에서 정한 공유 공간(조 공용 폴더 등)에도 올려요.

### 5-2. API 실패 기록

노트북 **API 실패 기록** 셀은 실패를 일부러 두 번 일으키고, 지금까지 ✅가 아닌 줄을 모두 모아 보여줘요. 아직 내 소스를 안 채운 상태로 모두 실행하면 이렇게 나와요.

```
❌ 실패 예시: 키 틀림: DART 010: 등록되지 않은 키예요. Secrets의 키 값을 확인해 주세요
❌ 실패 예시: 데이터 없음: DART 013: 조회된 데이터가 없어요. 아직 공시 전인 분기인지 확인해 주세요
```

| 단계 | 예시 | 결과 | 줄 수 | 확인 필요 | 메모 |
|---|---|---|---|---|---|
| 5 수동 입력 | 내 드라이브 출처카드 | ⏭ | 0 | 0 | USE_DRIVE = False (KFA_자료 폴더를 만들었으면 True로) |
| 1 공식 API | 내 소스 005930 | ⏭ | 0 | 0 | 아직 내 소스를 안 채웠어요 |
| 1 공식 API | 내 소스 000660 | ⏭ | 0 | 0 | 아직 내 소스를 안 채웠어요 |
| 1 공식 API | 내 소스 035420 | ⏭ | 0 | 0 | 아직 내 소스를 안 채웠어요 |
| 1 공식 API | 실패 예시: 키 틀림 | ❌ | 0 | 0 | DART 010: 등록되지 않은 키예요. Secrets의 키 값을 확인해 주세요 |
| 1 공식 API | 실패 예시: 데이터 없음 | ❌ | 0 | 0 | DART 013: 조회된 데이터가 없어요. 아직 공시 전인 분기인지 확인해 주세요 |

API가 실패하는 흔한 이유는 세 가지예요. 내 소스가 실패한 종목의 메모를 읽고 어디에 해당하는지 골라요.

| 종류 | DART에서 보이는 메시지 | 다른 사이트에서 흔한 모양 | 할 일 |
|---|---|---|---|
| 키 틀림 | `DART 010: 등록되지 않은 키예요` | `…가 401 응답을 줬어요. 키나 로그인이 필요해요` | 키를 다시 복사해 Secrets에 넣기 |
| 호출 제한 | `DART 020: 오늘 요청 한도를 넘었어요` | `…가 429 응답을 줬어요. 요청이 너무 잦아요. 1분 뒤 다시` | 기다렸다가 다시. 같은 요청을 반복해서 보내지 않기 |
| 데이터 없음 | `DART 013: 조회된 데이터가 없어요` | 응답은 왔는데 표가 비어 있음 | 날짜·분기·종목코드가 맞는지, 아직 발표 전인지 확인 |

호출 제한은 하루 한도를 넘겨야 나와서 노트북이 일부러 일으키지 않아요. 위 세 가지에 안 맞으면 "기타"로 적어요.

노트북 맨 아래에 **텍스트 셀**을 하나 만들어 이 표를 채워요. 실패가 하나도 없었으면 "실패 없음"이라고 적어요.

```
| 종목·요청 | 보인 메시지 | 종류 (키 틀림 / 호출 제한 / 데이터 없음 / 기타) | 한 일 |
|---|---|---|---|
|  |  |  |  |
```

## 6. 수동 입구 연결 확인

2회차에 만든 `KFA_자료` 폴더와 출처카드가 엔진으로 들어오는지 확인해요. 자동으로 못 받는 자료(리포트 숫자, PDF 속 표)는 이 입구로 들어와요.

### 6-1. 준비 상태 확인

```
내 드라이브
└─ KFA_자료              ← 이름의 밑줄까지 똑같이
   ├─ 출처카드           ← 구글 시트. 여기, files 폴더 밖에
   └─ files
      └─ 테스트_예시_2026-09.csv
```

- 시트 이름은 띄어쓰기 없이 **`출처카드`** 예요.
- 시트는 `KFA_자료` 바로 아래에 둬요. `files` 폴더 안이 아니에요.
- 출처카드 칸: `파일명, 출처, URL, 기준일, 신뢰도`. 선택으로 `수집 방법`(3 또는 5), `공시일`을 더할 수 있어요.
- 출처카드에 **적힌 파일만** 읽어요. 그중 `항목, 값, 단위, 기준일` 칸으로 정리한 CSV·엑셀만 읽고, 나머지는 이유를 한 줄씩 보여주고 건너뛰어요.

### 6-2. 실행

설정 셀에서 `USE_DRIVE = True`로 바꾸고(첫 글자 대문자) **런타임 → 모두 실행**. 드라이브 연결을 허락할지 묻는 창과 구글 계정을 고르는 창이 차례로 떠요. 두 창 모두 **`KFA_자료` 폴더를 만든 같은 구글 계정**을 골라서 허용해요(권한 목록이 나오면 모두 체크). 연결되면 `Mounted at /content/drive`가 나와요.

아래는 출처카드 한 줄과 CSV 파일 하나로 시험한 결과예요.

출처카드:

| 파일명 | 출처 | URL | 기준일 | 신뢰도 |
|---|---|---|---|---|
| 테스트_예시_2026-09.csv | 테스트 | https://example.com | 2026-09-30 | 하 |

`files/테스트_예시_2026-09.csv`:

```
항목,값,단위,기준일,기준,확인
테스트 매출,100,억원,2026-09-30,해당 없음,✅
테스트 영업이익,10,억원,2026-09-30,,
```

노트북 **5. 수동 입구** 셀 결과:

```
✅ 내 드라이브 출처카드: 2줄 (확인 필요 2줄)
```

| 항목 | 기준 | 상태 | 비고 |
|---|---|---|---|
| 테스트 매출 | 해당 없음 | 확인 필요 | 출처카드: 테스트_예시_2026-09.csv; ⚠ 공시일 비어 있음 |
| 테스트 영업이익 | (빈칸) | 확인 필요 | 출처카드: 테스트_예시_2026-09.csv; ⚠ 기준 비어 있음; ⚠ 공시일 비어 있음; ⚠ 손으로 옮긴 값: 원문과 대조 |


| source_id | 출처 | 출처 URL | 수집 방법 | 신뢰도 | 기준일 범위 | 줄 수 |
|---|---|---|---|---|---|---|
| S3 | 테스트 | https://example.com | 5 수동 입력 | 하 | 2026-09-30 | 2 |

### 6-3. 카드 줄이 확인 필요로 뜨는 이유와 푸는 법

출처카드로 들어온 줄은 꼬리표 세 가지가 비기 쉬워요. 카드에는 출처·URL·기준일·신뢰도만 있어서, 나머지는 파일이 알려줘야 하거든요.

| ⚠ 이유 | 왜 | 푸는 법 |
|---|---|---|
| `기준 비어 있음` | 연결인지 별도인지 코드가 알 수 없어요 | 파일에 `기준` 칸을 만들고 `연결` / `별도` / `해당 없음`(거시 지표처럼 회사 숫자가 아닐 때) |
| `공시일 비어 있음` | 그 숫자가 언제 알려졌는지 코드가 알 수 없어요 | 파일에 `공시일` 칸을 만들고 날짜(리포트 발간일 등) 또는 `해당 없음`. 한 파일의 날짜가 모두 같으면 출처카드에 `공시일` 칸을 만들어 **한 번만** 적어도 돼요 |
| `손으로 옮긴 값: 원문과 대조` | 사람이 옮긴 숫자는 오타가 있을 수 있어요 | 원문과 대조한 뒤 파일의 `확인` 칸에 `✅` 또는 `O` |

위 시험 파일로 보면, 1줄째는 기준(`해당 없음`)과 확인(`✅`)이 있어서 공시일만 걸렸고, 2줄째는 기준·확인이 빈칸이라 세 가지가 다 걸렸어요.

파일 칸과 출처카드 칸이 둘 다 있으면 **파일 칸이 먼저**예요. 기준일도 같은 방식이에요. 그래서 대부분의 줄은 카드에 한 번 적고, 날짜가 다른 줄만 파일에 따로 적으면 돼요.

고친 결과는 이렇게 나와요.

- 파일에 `기준`·`공시일`·`확인` 칸을 모두 채운 경우 (`해당 없음`, `해당 없음`, 1줄째 `✅` · 2줄째 `O`):
  ```
  ✅ 내 드라이브 출처카드: 2줄 (확인 필요 0줄)
  ```
- 파일은 그대로 두고 출처카드에 `공시일` 칸만 더한 경우: 1줄째는 형식 통과, 2줄째는 `⚠ 기준 비어 있음; ⚠ 손으로 옮긴 값: 원문과 대조`가 남아 확인 필요 1줄이에요. 공시일은 풀렸지만 기준과 확인은 파일에서 채워야 해요.

### 6-4. CSV 저장할 때

- **메모장**에서 만들고, 저장할 때 파일 형식을 **모든 파일**, 인코딩을 **UTF-8**로 골라요. 파일 이름 끝은 `.csv`.
- **엑셀로 열었다가 저장하지 않아요.** 엑셀이 날짜 모양을 바꾸거나 `000660` 같은 숫자 앞의 0을 지울 수 있어요.
- 각 줄은 맨 앞부터 바로 시작해요. 줄 앞 띄어쓰기는 이제 코드가 지워 주지만, 처음부터 안 넣는 게 안전해요.

## 10. 막혔을 때

| 보이는 메시지 | 원인 | 해결 |
|---|---|---|
| `DART 키가 없어요` (⏭) | Secrets에 키가 없거나 노트북 액세스가 꺼짐 | 🔑에서 스위치 켜고 **모두 실행** 다시 |
| `DART 010: 등록되지 않은 키예요` | 키를 잘못 복사함 (앞뒤 공백, 일부만 복사) | DART 오픈API 이용현황에서 다시 복사 |
| `DART 013: 조회된 데이터가 없어요` | 그 해 사업보고서가 아직 안 나옴 | `YEAR`를 한 해 전으로 (예: 2025 → 2024) |
| `DART 020: 오늘 요청 한도를 넘었어요` | 하루 요청 수를 넘음 | 내일 다시 |
| `…: 상장사 목록에 없어요` | 종목코드가 틀림 | 6자리, 앞의 0까지, 따옴표 안에 |
| `'출처 카드'를 출처카드로 읽었어요` (오류 아님) | 시트 이름에 띄어쓰기가 들어감. 코드가 찾아서 읽었어요 | 그대로 써도 돼요. 시트 이름을 `출처카드`로 바꾸면 이 줄이 안 나와요 |
| `'출처카드'라는 구글 시트를 못 찾았어요. 시트 이름을 확인해 주세요` | 띄어쓰기를 빼고 비교해도 같은 이름의 시트가 없음 | 시트 이름을 `출처카드`로. 설정 셀의 `CARD_SHEET`도 확인 |
| `'출처카드'와 띄어쓰기만 다른 시트가 2개예요: [...]` | `출처 카드`와 `출처카드 ` 같은 시트가 여럿 | 쓸 시트 하나만 이름을 `출처카드`로 바꾸기 |
| `Mounted at /content/drive` 다음에 `'출처카드'라는 구글 시트를 못 찾았어요` | 드라이브는 연결됐는데, 두 허용 창에서 서로 다른 구글 계정을 골랐을 수 있음 | 두 창에서 서로 다른 계정을 골랐는지 확인. 두 창 모두 `KFA_자료`를 만든 계정으로 |
| `내 드라이브 맨 위에 'KFA_자료' 폴더가 없어요` | 폴더 이름이나 위치가 다름 | 내 드라이브 맨 위에 `KFA_자료` (밑줄까지 똑같이) |
| `출처카드에 없는 칸: [...]` | 출처카드 첫 줄의 칸 이름이 다름 | `파일명, 출처, URL, 기준일, 신뢰도`를 그대로 |
| ⏭ `files/ 폴더에 이 이름의 파일이 없어요` | 카드의 파일명과 실제 파일 이름이 다름 | 띄어쓰기·확장자(`.csv`)까지 똑같이 |
| ⏭ `'항목·값·단위·기준일' 칸 모양이 아니에요. … 지금 칸: [...]` | 파일 첫 줄이 `항목,값,…`이 아님 | 메시지 끝 "지금 칸" 목록을 보고 첫 줄을 `항목,값,단위,기준일,…`로 |
| ⏭ `'항목·값·단위·기준일' 칸 모양이 아니에요. 3단계 예시처럼 items로 바꿔 주세요` (뒤에 "지금 칸"이 없음) | 이 가이드가 올라오기 전의 사본. CSV 줄 앞에 띄어쓰기가 있으면 이 메시지가 났어요 | 1번 링크로 노트북을 새로 열기. 또는 CSV 줄 앞 띄어쓰기 지우기 |
| ⏭ `출처카드 N줄 중 읽을 수 있는 숫자 파일이 없어요` | 카드의 파일을 하나도 못 읽음 | 바로 위에 나온 ⏭ 이유를 하나씩 보기 |
| `CSV 글자를 못 읽었어요` | 한글 인코딩 문제 | 메모장에서 UTF-8로 다시 저장 |
| `같은 사실(종목코드\|항목\|기준\|기준일\|출처)이 두 줄 이상 있어요` | 같은 자료를 두 번 붙임 | 같은 셀을 두 번 붙였는지, 출처카드에 같은 파일을 두 번 적었는지 확인 |
| `[S#] …: 한 출처인데 신뢰도이(가) 여러 개예요` | 같은 출처·주소인데 신뢰도를 다르게 적음 | 출처카드에서 하나로 맞추기 |
| `…가 429 응답을 줬어요. 요청이 너무 잦아요` | 내 소스 사이트의 호출 제한 | 1분 뒤 그 셀만 다시 실행 (셀 클릭 → Shift + Enter) |
| `…에 연결하지 못했어요` / `인터넷 연결 문제` | 사이트가 잠깐 안 됨 | 1분 뒤 그 셀만 다시 실행 |
| `예상 못 한 오류 (...)` | 위에 없는 문제 | 셀을 한 번 더 실행. 그래도 안 되면 에러 종류를 조 톡방에 공유 |
